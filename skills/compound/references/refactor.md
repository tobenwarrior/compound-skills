# Refactor

Preserve each caller's accepted inputs, outputs, errors and defaults. An extracted helper needs the interface its current callers require; a common name does not authorize a common policy. A new signature needs an actual caller or an explicit API requirement.

Read the named callers and tests first. Search for a missing reference only when needed. Inspect history or external code only for a concrete compatibility question.

1. Identify the shared operation and differing policies once. Keep nonshared validation, public exceptions and I/O with their existing owners. Make differing policies required arguments at migrated call sites unless a requested/existing API specifies defaults. Choose one preserving interface and use it throughout the change.
2. Determine coverage from the existing assertions before running tests. If existing caller assertions already cover the affected behavior, run them as the baseline. Otherwise add missing cases together per file using existing fixtures, then run the baseline. Run it once with the documented command and environment before source edits. Call existing APIs, with original observed values/errors; do not import the proposed helper. Keep those assertions unchanged after extraction. A failing baseline must be resolved first.
3. After the baseline passes, identify the definitions being retired. When the host supports it, delete those definitions, replace their calls and add the shared helper in one patch. Check uncertain dynamic or external references before deleting code. Retain wrappers when external compatibility requires them. Keep caller-specific policy with its owner.
4. Review the diff and new files once. Confirm each retired definition and call is gone before running the retained assertions and required checks. Use an exact-name search in the affected source only if the diff leaves a gap. In an absence check, `rg` exit 1 means no matches. Treat search errors as failed checks. Cover relevant error and boundary cases. Prevent Python bytecode with `PYTHONDONTWRITEBYTECODE=1` or `python -B`. Leave existing caches alone unless they affect correctness or the project requires cleanup. Batch the final suite and independent diff or migration checks when supported. Reuse inspected content and report authorized behavior changes as scope changes.

Skip optional compilation and repeat suites after a pass. Run extra probes only for a specific unresolved coverage question or an explicit user or project requirement. Reuse passing evidence for unchanged inputs. Do not temporarily introduce a known-bad implementation to repeat evidence already provided by the baseline. Report the outcome, checks and limits.
