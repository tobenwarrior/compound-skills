# Refactor

Preserve each caller's accepted inputs, outputs, errors and defaults. An extracted helper needs the interface its current callers require; a common name does not authorize a common policy.

1. Identify the shared operation and differing policies once. Keep nonshared validation, public exceptions and I/O with their existing owners. Make differing policies required arguments at migrated call sites unless a requested/existing API specifies defaults. Choose one preserving interface and use it throughout the change.
2. Determine coverage from the existing assertions before running tests. If existing caller assertions already cover the affected behavior, run them as the baseline. Otherwise add missing cases together per file using existing fixtures, then run the baseline. Run it once with the documented command and environment before source edits. Call existing APIs, with original observed values/errors; do not import the proposed helper. Keep those assertions unchanged after extraction. A failing baseline must be resolved first.
3. After the baseline passes, batch the shared helper and its caller changes when the host supports it. Check uncertain dynamic/external references before deleting code; preserve external compatibility. Do not broaden the helper merely to absorb caller-specific policy.
4. Run the retained assertions and required checks, including relevant error and boundary cases. Use supported test options to avoid untracked byproducts, such as `python -B` for ordinary Python test runs. Leave existing caches alone unless they affect correctness or the project requires cleanup. Batch the final suite and independent diff or migration checks when the host supports it. Review the diff and new files once, reusing inspected content. Correct unexplained mismatches in the implementation; report authorized behavior changes as a scope change.

Report the outcome, recorded checks and limits directly. Settled interface choices stay settled unless a check fails or a real caller requirement appears. Do not reconsider defaults or imagined direct-call signatures while preparing the final answer. Use extra probes only for a specific unresolved coverage question or an explicit user/project requirement. Assert their expected behavior against retained evidence. Do not temporarily introduce a known-bad implementation to repeat evidence already provided by the baseline. Skip duplicate checks and cosmetic follow-ups after completion.
