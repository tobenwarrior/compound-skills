# Debug

Capture a concrete failing input, expected result, actual result, and execution surface. Reproduce against the relevant version before choosing a fix. Turn a known failing case into its regression before investigating further. Use a separate probe only for a specific question the test cannot answer. If the failure is intermittent, record conditions and instrument the narrowest uncertain boundary within the authorized environment.

Form competing hypotheses and run checks that distinguish them. Follow the first incorrect state or effect back to its cause. A guard is appropriate when it handles a legitimate domain state; otherwise it may hide a broken invariant.

Run the targeted regression before source edits and confirm it fails on the reported behavior. Use that failure as the pre-fix evidence. Reuse existing fixtures, then make the smallest causal correction. For split paths, test the required property directly. One operation's success does not prove another's preconditions. Cover supported input categories and equivalent values across paths in both orders. Remove instrumentation and changes whose hypothesis was refuted.

Verify the correction on the same surface. If the final suite includes the regression, its passing result verifies the fix. Go straight to that suite and the diff check unless the project requires a separate check or one addresses a specific gap. Finish once the checks pass. Reuse that result while checked inputs and environment are unchanged. Use documented test options that avoid untracked output, such as `python -B`. Batch independent final checks. Unit tests, type checks, and compilation each establish different facts. If the original surface is unavailable, report the narrower evidence and unresolved limitation instead of declaring the defect gone.
