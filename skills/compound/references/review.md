# Review

Read the requested diff once with ordinary context. For a known commit, start with `git show --format=oneline --no-ext-diff --unified=3 <commit>`. Reuse the visible hunks. Read specific caller and test ranges only to settle gaps in the evidence. For a changed default, callback, shared helper, or retry, trace a reachable edge case against prior behavior or the documented contract. For a shared helper, identify the changed call sites in the diff and compare each caller’s prior behavior. Cite the affected call site when a finding depends on one caller’s policy. Check explicit zero or empty values, when deferred code reads state, or whether a side effect precedes an error. Capture each confirmed finding as soon as its source evidence is clear. Once the diff and relevant callers are covered, deliver the findings. Report the confirmed findings if further checks are blocked or the tool budget is nearly spent.

When a diff changes startup, shutdown, cancellation, or a shared runtime boundary, identify the test that exercises the affected production path with that behavior intact. Mock external I/O. If tests replace the behavior under review, report the coverage gap and run one targeted check when permitted.

Check correctness, concurrency, and unsupported assumptions. Flag concrete maintenance problems such as unnecessary layers, duplicate state, unclear ownership, and misleading names. Apply project conventions without turning preferences into defects.

Use independent reviewers for distinct uncertainties when the host supports it and the benefit warrants the cost. Give them the same intent and artifact, then verify findings yourself. Reviewer agreement is supporting evidence, not proof.

Return actionable findings with location, triggering condition, impact, and supporting evidence. Keep each finding and its evidence together. Separate confirmed defects, unresolved questions, and optional improvements. Use a permitted check when source cannot settle a specific finding or when required. Prefer one documented check that could change that finding. Confirm permission before creating scratch files or running the check. A review remains read-only unless changes are authorized. After an execution or probe-setup denial, continue from source; do not write alternate scripts, switch runners, relocate artifacts or retry the blocked operation. State the verification limit once. Do not include unexecuted repro scripts or full patches unless requested.
