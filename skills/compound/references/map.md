# Code maps

Use named files and current context first. Query only for unknown files or dependencies, and reuse an unchanged answer. Search focused files and import neighbors for the relevant statements. Read nearby lines to confirm behavior and callers in source or tests. Missing entries prove nothing: coverage is bounded and import links are not a complete call graph. Use native search for reported limits. Skip mapping for activation-only requests, non-code work, and tasks that name their file or supply the code.

`code_map.py --cache-read-only` reuses fingerprint-validated metadata from an existing cache, parsing missing or changed files in memory without writing or starting a service. `--no-cache` bypasses the cache entirely. For write-authorized tasks, omit both to start or reuse the shared local service. Its index reuses unchanged file metadata and checks additions, edits, and deletions. Agent queries use bounded waits for index completion. Text and JSON queries use a temporary focus and preserve the saved viewer query. Changing the query reranks the index without forcing a rebuild; `--refresh` requests one. Helpers truncate service queries to 512 characters; the API rejects longer ones. Invalid local cache data is skipped so the map can reparse source. A failed tracked-file inventory reports an error and preserves the previous index and cache for recovery. When Git status exceeds the freshness limit, automatic viewer checks run at most every 30 seconds. Explicit CLI queries still check immediately. If only the untracked scan fails, the map shows tracked files with a partial-coverage warning and keeps the complete disk cache. If service startup fails, the helper reports it and falls back to a bounded local scan.

For symbol definitions or references, prefer host-native navigation. If unavailable, this guide offers bounded lexical lookup and an opt-in adapter for a user-authorized, trusted language server; lexical occurrences are not semantic references.

For denied local cache or network access, use the host's normal approval flow and retry the cached command once. Keep security settings unchanged; report the local fallback if still unavailable.

## Symbol lookup

When the host has no suitable symbol or reference tool, run `python3 -B <installed-skill-dir>/scripts/symbol_lookup.py --repo <repo-root> --symbol <symbol>`. Quote untrusted paths and names for the host shell or pass them as argument vectors. It returns bounded JSON with exact outline matches and lexical occurrence locations, without source snippets. Python methods include the declaring class and accept qualified names such as `AppContext.pop`. Occurrences match the supplied spelling, including in comments and strings. Use semantic navigation for resolved references. By default the reference scan covers at most 1,000 files, 256 KiB per file, 8 MiB total, and 3 seconds after model setup; JSON defaults to 12 KiB. Check the reported coverage and limits, then confirm in source. By default it reuses a validated cache read-only without starting the service or writing files; `--no-cache` bypasses it. On platforms without safe no-follow directory-relative opens, occurrence scans fail closed and report the gap. For repeated lookups in write-authorized work, add `--service` to start or reuse the authenticated local service and its bounded memory-only postings index. Postings contain words from code, comments, and strings; they are never persisted, and stopping the service clears them. The default and `--no-cache` remain read-only and never start the service.

To verify the enclosing symbol of a Python citation, run `python3 -B <installed-skill-dir>/scripts/symbol_lookup.py --repo <repo-root> --location <relative-file:line>`. Repeat `--location` or combine it with `--match` for up to 12 queries in one command. It checks the named files against Git and reads each UTF-8 Python file once. Results give the exact enclosing symbol and line range for each location in order. A decorated function or class owns its decorator lines, and its range starts at the first decorator. Module-level lines return a null symbol. Add `--excerpt 2` to include the cited line and two nearby lines on either side in the same result. The excerpt accepts 0–8 lines of context. Location lookup reads no map cache and starts no service. File, total byte, output, and timeout limits apply to this mode. Ranking and cache options are for symbol-name lookups.

For an exact statement in a known Python file, use `--match <relative-file> <literal-text>`. Results follow query order across both options. Each result lists up to three matching lines with their enclosing symbols and reports whether more matched. Matches are case-sensitive substrings, including in comments and strings. Use `--excerpt 0` to return the matching line itself, or a larger radius for context. A file used by several pairs is read and parsed once.

Use `lookup --find <literal>` to search tracked Python files and verify the enclosing symbols in one command. Searches cover `.py` and `.pyw` files with any extension casing. Repeat `--find` for several statements and `--path <file>` for exact repository-relative files. The result includes the matching line by default. A batch reports unmatched terms by their 1-based argument order on stderr and keeps JSON matches on stdout. Narrow the paths or literals when the search exceeds 12 matches or 64 KiB. With no matches, the command returns an empty list.

Use `lookup --find-in <file-or-directory> <literal>` when each statement needs its own scope. Repeat for up to 12 pairs. A directory searches its tracked Python files, and a repeated source line appears once. The same match and byte limits apply to the whole batch. Unmatched pairs are reported by their 1-based argument order on stderr. Stdout contains the JSON matches.

To reuse an existing scoped Git search, pass its `git grep -n -z` output to `lookup --grep-input`. Optional Git column numbers are accepted. The lookup verifies each matched line against the current source. If a line changed, rerun the lookup.

```bash
git -C "<repo-root>" grep -n -z -I -F --no-color -e "<statement>" -- "<python-file>" |
  python3 -B "<map-skill-dir>/scripts/map.py" lookup --repo "<repo-root>" --grep-input --excerpt 0
```

## Optional semantic navigation

When native navigation is unavailable and the user authorizes a trusted installed language server, use `python3 -B <installed-skill-dir>/scripts/lsp_lookup.py --repo <repo-root> --file <relative-path> --line <1-based-line> --column <1-based-column> --server-command-json '["clangd","--background-index=false"]'`. Input columns count Unicode code points; output columns use the negotiated LSP encoding. Output is bounded JSON with workspace-relative locations and coverage, without source snippets. The adapter checks the source and returned paths against one repository inventory. Repeated locations in a response share one path validation per URI. It starts and shuts down a stdio server per lookup and requires both definition and references capabilities; server-specific setup may be needed. The server is launched only when explicitly supplied; it receives source text, inherits the caller's environment and permissions, and may execute workspace tooling. It is not sandboxed. Never auto-install or run an untrusted server; use the lexical helper when unavailable.

## Live viewer

The viewer uses the hey.trading cream-and-green theme independently of the host app’s appearance. After a plugin update, reopen the map to refresh its service assets, then reload existing browser tabs.

Use the [map utility](../../map/SKILL.md) for a visual request. It starts or reuses one loopback service at `http://127.0.0.1:43127/` and opens the registered project. `COMPOUND_MAP_PORT` can select another port. Opening again reuses the index. Saved project links restore on demand after a restart, and an open viewer reloads when it sees the new service instance. It creates no HTML snapshot. Cold indexing runs in the background; the page stays responsive and retains its last map during incremental updates. It does not restructure source code.

Map viewing authorizes local cache and service startup only, without repository edits or onboarding cleanup. The helper's `status` and `stop` subcommands inspect or stop this shared service. It runs until stopped or the machine session ends; the next coding or map request starts it again. It scans only repositories registered by those requests, not every project at login.

Python 3.11+ and Git are required; the core adds no dependency, provider, database, or watcher. Optional semantic lookup requires a separately installed, trusted language server. Python receives AST outlines; JS/TS receives bounded outlines and local imports, including supported relative tsconfig inheritance, project aliases, and workspace package exports. Go, Rust, Java, C/C++, C#, Ruby, PHP, Swift, and Kotlin receive bounded heuristic declaration outlines; the first 256 Ki characters are examined. Go module-local imports and Rust module declarations/uses also produce bounded heuristic file links. Build tags, macros, conditional modules, external crates, and other languages still require native search; Go/Rust import links are read from the first 256 KiB of each file, and partial results are disclosed. Other recognized files have metadata only. These are not language servers: computed imports, cross-language references, and call hierarchies require native search. Git-listed `build/` and `dist/` source is included; `vendor/` and `node_modules/` are excluded. Each pass reads at most 64 MiB and 1 MiB per file; beyond those limits, metadata remains visible with partial-outline coverage. PHP outlines recognize mixed-case tags and declarations with inline attributes. They skip inline HTML and backtick strings. The service indexes up to 20,000 files, projects up to 5,000 per response, and draws up to 20,000 links. Search ranks against the larger index; counts distinguish indexed files from the current view. Neighborhoods, impact, and import traces are limited to that view. Import traversal indicates structural relationships, not runtime calls. Normal exclusions appear under coverage; failures and limits remain warnings.

Metadata includes line counts, export hints, unresolved imports, Git changes, and bounded recent co-change history. An exact repository-relative path query, with or without `./`, puts an indexed match first. In-process queries also consider the exact path first when applying the inventory cap and source read budget. A lowercase spelling can match a mixed-case symbol such as `methodview` and `MethodView`. An exact mixed-case or underscore-separated name can put its indexed definition ahead of files that match only its component words. An explicit test word or an underscore-delimited test name keeps test files in contention. A class name such as `TestCase` keeps its exact-definition priority without promoting unrelated test files. The remaining results are ranked by distinctive query words in paths, symbols, and bounded source text read per query and never stored; larger and widely imported code files, current changes, and co-changes of matches rank higher, and tests rank lower unless the query mentions tests. Path matching recognizes `ctx` as an abbreviation for context. The map reads the first 50 candidates. If that scan and the metadata yield no lexical match, it can read up to 200 candidates total within the same 8 MiB budget. When a query has evidence for all but one keyword, the map can scan up to 50 more files for the missing keyword within that budget. The first additional hit gets one focus slot after the three leading results. Exact paths skip this extra scan in the ranked map. For an exact indexed path, agent text shows that file, up to eight indexed declarations and its import hints within the text limit. Once indexed, text responses use that row directly in the service and in-process CLI. A bare mixed-case or underscore-separated symbol, or a qualified Python name such as `AppContext.pop`, gets the same shortcut when it has one indexed defining file. Focused text names the declaring class for Python methods. Ambiguous symbols, multiword queries, and indexes that hit a coverage cap use normal ranking. Confirm those hints in source. Outlines retain up to 512 symbols per file and disclose truncation. For a topic query, agent text expands only matching symbols (up to eight per file), while retaining the ranked file paths, imports and coverage. Without a query it keeps orientation symbols. Text defaults to a 2,500-character cap and is rendered by the service without transferring the full index. At that cap or lower, focused topic text shows imports for the first four matches and retains later paths and matching declarations as space permits. Set `--max-chars` above the default for import hints on later rows. When focused text reaches the limit, it fits complete file paths before adding symbol hints and detail. Compact topic summaries keep every ranked matching path that fits, even when the leading rows need to be condensed.

Metadata and service state stay in Compound's user cache, outside the repository. Normal APIs contain no source bodies. Explicit **Source** or symbol selection reads a bounded 64 KiB preview of an indexed file without caching its body. The loopback service validates indexed paths and rejects private files, traversal, symlinks, and foreign origins; any local process can read its maps and source previews. Keep generated maps out of commits; chat summaries enter normal context.

On POSIX, each query pins the canonical repository directory once for its candidate content reads. Root ancestors are checked when pinned, relative components on every file open; symlinks and non-regular files remain rejected. A concurrent root rename keeps that query anchored to the original directory. The descriptor closes after the query, and content is not cached.

For a focused query, text lists candidates with matching paths, symbols/declarations or content from the bounded ranking scan. These are lexical navigation suggestions; read only those relevant to the task. With no matches, use native search or refine the query. JSON retains the complete `files` and ranked `focus`, adding `query_matches` for the current query; the viewer index and unfocused outline stay complete.
